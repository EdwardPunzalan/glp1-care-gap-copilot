## What changed since 0.1.2

### Third-party egress: eliminated

The 0.1.2 review's largest section assessed the Anthropic LLM call — the
PHI-minimal payload, the allow-list tests, the sanitization of model output.
**None of that surface exists anymore.** The model path was removed in 1.1.0
because it billed per render on a hot path, and the templated fallback it
degraded to was already the sentence clinicians saw.

Verified at this version: no `Http()`, `CanvasFhir`, `requests`, `httpx`,
`urllib`, `LlmAnthropic`, `api_key`, or `Bearer` anywhere in the plugin. The
plugin makes **zero** network calls. Nothing patient-derived leaves the
instance, so there is no egress to minimize, audit, or trust.

### Sensitive variables: none remain

`ANTHROPIC_API_KEY` was the plugin's only variable marked `sensitive: true`, and
it was removed with the LLM feature. The manifest now declares **12** variables,
all non-sensitive clinical thresholds and matching lists that operators need to
read back in plaintext to verify.

The redaction machinery added in the previous review (`SENSITIVE_VARIABLES`,
`_loggable()`) was **deliberately kept** with an empty member set. It is held to
the manifest by `test_every_sensitive_manifest_variable_is_redacted_in_logs`, so
marking a future variable `sensitive: true` without covering it fails CI. This
converts a latent leak into a build error.

### Lab ordering: from inference to declaration

1.2.0 replaced `order_name__icontains` matching with `LAB_TEST_ORDER_CODES`, an
explicit `lab name:order code` map. Security-relevant consequences:

- The plugin no longer derives which clinical test to order from fuzzy text
  matching. Against the real XPC Lab catalog the old approach matched **8**
  tests for "comprehensive metabolic panel" and would have bundled all of them
  into one order.
- Each configured code is re-validated against the partner's catalog at render
  time (`order_code__in`), so a stale mapping degrades to "no button" rather
  than emitting a command Canvas would reject.
- Malformed map entries are dropped with a warning rather than guessed at.

### Patient Data Scoping — ✅ Pass

Unchanged from the prior review and re-verified. Every query touching patient
data is constrained to the target patient, taken from `self.event.target.id`:

| Location | Model | Scoping |
|---|---|---|
| `cohort.py` | `Condition`, `Medication` | `for_patient(patient_id)` |
| `gaps.py` | `Observation` | `for_patient(patient_id)` |
| `gaps.py` | `LabValue` | `report__patient__id=patient_id` |
| `gaps.py` | `Appointment` ×2 | `patient__id=patient_id` |
| `dedupe.py` | `Task` | `patient__id=patient_id` |

`card.py`'s `LabPartner` and `LabPartnerTest` queries remain intentionally
unscoped — they read an instance-level catalog containing no patient data.
`patient_filter` (the fan-out mechanism) is never used.

### Writes — ✅ N/A

The plugin performs **no database writes**. No `.save()`, `.create()`,
`.update()`, or `.delete()` appears in the source. Its only effect is one
protocol card; any chart write happens through a command a clinician explicitly
reviews and signs.

### Log Hygiene — ✅ Pass (both prior findings resolved)

**LOW-1 (0.1.2): redaction depended on parser choice** — resolved. All logging
parsers render values through `_loggable()`, which masks by variable name. Three
tests enforce it, one of which reads `CANVAS_MANIFEST.json` directly.

**LOW-2 (0.1.2): raw exception text on the LLM path** — resolved by deletion.
That code path no longer exists.

All remaining log statements were re-reviewed. None emits PHI or a credential.
The handler's two INFO lines record booleans and gap-key lists with no patient
identifier — deliberately, since logging patient ids would itself be a concern.

## Recommendations

None. No HIGH, MEDIUM, or LOW findings at this version.

## Verdict

**✅ PASS** — clean.

This version has a smaller attack surface than the one previously reviewed. It
has no endpoints, no inbound requests, no credentials, no network I/O, no
writes, and no sensitive configuration. Patient data is read-only and
patient-scoped everywhere. The one previously flagged class of risk — data
leaving the instance — was removed entirely rather than mitigated.
