## What changed since the 1.0.0 wrap-up

**1.1.0 — LLM narrative removed.** The model billed per render on a path that
fires for every chart open, and the templated fallback it degraded to was
already the sentence clinicians saw, since no API key was ever configured. The
narrative is now always deterministic. This removed the plugin's only network
call and its only third-party transmission; `ANTHROPIC_API_KEY`, `LLM_MODEL`,
and `ENABLE_LLM_RATIONALE` left the manifest (14 → 11 variables), and `_flag`
went with them as it had no remaining callers.

**1.2.0 — lab ordering by explicit code map.** `order_name__icontains` matching
was wrong against a real catalog in both directions: XPC Lab lists 8 tests
containing "comprehensive metabolic panel" and none named plain "lipid panel".
`LAB_TEST_ORDER_CODES` now maps each expected lab to one operator-chosen order
code (11 → 12 variables), re-validated against the partner catalog at render
time.

Both reviews were re-run against 1.2.0 and both improved:
`security-review-20260812-151551.md` (now zero findings — the two prior LOWs are
resolved, one by deletion) and `db-performance-review-20260812-151551.md`.

### Follow-ups for whoever picks this up next

1. If a deployment configures many entries in `REQUIRED_LAB_NAMES`, revisit the
   per-lab query shape (see the DB performance review)
2. `LAB_TEST_ORDER_CODES` is instance-specific — each Canvas instance needs its
   own codes read from Admin › Health Gorilla › Lab tests
3. The plugin has no sensitive variables today; if one is added, mark it
   `sensitive: true` **and** add it to `SENSITIVE_VARIABLES` in `config.py` — a
   test enforces this pairing
